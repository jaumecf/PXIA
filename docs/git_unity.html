Control de Versions amb Git & Git LFS a Unity

Guia de consulta ràpida per a configurar, gestionar i mantenir projectes de Unity amb Git sense perdre fitxers, corrompre metadades ni saturar el repositori remot.

1

Conceptes Clau de Git per a Videojocs

Git és un sistema de control de versions distribuït. Per a entendre el seu funcionament, cal conèixer els tres estats pels quals passen els teus canvis:

Working Tree

Són els fitxers reals del projecte que estàs modificant al teu disc dur des de Unity o la teva IDE.

Staging Area

Zona d'espera on prepares els canvis seleccionats amb git add abans de confirmar-los.

Commit

Una instantània immutable de la feina seleccionada, registrada amb data, autor i missatge dins la història.

Recordatori d'Or: Git no és una còpia de seguretat automàtica dels canvis en temps real. Un canvi local sense commit i sense push no està protegit per l'historial.
2

Configuració Inicial i Entorn de Desenvolupament

A. Identitat Global i Verificació

Executa aquestes comandes per a configurar la teva signatura pública i verificar les eines instal·lades:

# Comprova la instal·lació de Git i LFS
git --version
git lfs version

# Configura el teu nom i correu d'autor (no són les credencials d'accés a GitHub!)
git config --global user.name "ElTeuNom"
git config --global user.email "el_teu_email@alumne.cat"

# Comprova la configuració desada
git config --global --list

B. Ajustos Obligatoris a Unity

Obre el teu projecte de Unity i verifica aquests dos paràmetres a Edit > Project Settings > Editor:

  • Version Control Mode: Visible Meta Files (assegura que cada asset acompanyi el seu fitxer .meta associat).
  • Asset Serialization Mode: Force Text (desa escenes i prefabs com a YAML llegibles per a permetre la comparació de canvis en text).

Nota avançada: Per a la integració d'escenes col·laboratives, Unity inclou l'eina de fusió intel·ligent UnityYAMLMerge (Smart Merge).

3

Inicialització d'un Projecte Unity (2 Escenaris)

Escenari A: Repositori Remot Buit (Recomanat)

Si ja tens el projecte creat localment i crees un repositori nou a GitHub sense README ni .gitignore inicial:

cd ruta/del/projecte

git init
git remote add origin https://github.com/usuari/repo.git

# Crea el teu .gitignore abans de fer add!
git add .
git commit -m "chore: initial project setup"

git branch -M main
git push -u origin main

Escenari B: Repositori Remot amb Contingut Inicial

Si el repositori de GitHub es va crear amb un README o llicència prèvia, el millor camí és clonar primer:

# 1. Clona el repositori buit al teu disc
git clone https://github.com/usuari/repo.git

# 2. Copia els fitxers del projecte Unity dins la carpeta clonada
# 3. Accedeix a la carpeta, afegeix i publica
cd repo
git add .
git commit -m "feat: afegit projecte base de Unity"
git push origin main

Plantilla `.gitignore` Oficial i Neteja d'Índex

Unity genera carpetes temporals que ocupen gigabytes de memòria i es tornen a generar automàticament (com Library/ o Temp/). Només s'han de versionar Assets/, Packages/ i ProjectSettings/.

.gitignore Unity Standard Template

/[Tt]emp/
/[Oo]bj/
/[Bb]uild/
/[Bb]uilds/
/[Ll]ogs/
/[Uu]ser[Ss]ettings/
/[Mm]emoryCaptures/

# Fitxers de Solució d'IDE (Visual Studio, Rider, VS Code)

/*.suo
/*.user
/*.userprefs

# Arxius del sistema operatiu

Què passa si ja vaig pujar la carpeta Library/ per error?

Si una carpeta o fitxer ja ha estat inclosa a la història de Git, afegir-la al .gitignore NO l'eliminarà de l'índex. Has d'eliminar-la explicitament de la memòria cau de Git: 

# Elimina la carpeta Library/ de la memòria de Git sense esborrar-la del teu disc dur
git rm -r --cached Library/
git commit -m "chore: eliminada la carpeta Library del control de versions"

# Diagnostica quina regla ignora un fitxer
git check-ignore -v Library/
5

Configuració de Git LFS (Large File Storage)

Git LFS substitueix els fitxers pesats (models 3D, textures, àudios) per punters de text lleugers al repositori principal, emmagatzemat els binaris en un servidor optimitzat. 

# 1. Instal·la l'extensió Git LFS al teu entorn local
git lfs install

# 2. Rastreja les extensions d'assets multimèdia més freqüents
git lfs track "*.psd"
git lfs track "*.fbx"
git lfs track "*.obj"
git lfs track "*.wav"
git lfs track "*.mp3"
git lfs track "*.png"
git lfs track "*.tga"
git lfs track "*.exr"

# 3. MOLT IMPORTANT: Deses el fitxer .gitattributes generat
git add .gitattributes
git commit -m "chore: configuració de Git LFS per assets multimèdia"
6

Cicle de Treball Diari (Rutina Individual)

Pas a Pas d'un Desenvolupament Segur

# 1. Comprova en quin estat està el projecte
git status

# 2. Revisa els canvis introduïts al codi/projecte
git diff

# 3. Prepara els fitxers que vols guardar
git add .

# 4. Revisa exactament què entrarà al commit (Staging Area)
git diff --cached

# 5. Registra una versió estable amb un missatge clar
git commit -m "feat: afegeix la mecànica de doble salt"

# 6. Publica els canvis al repositori remot
git push origin main

Nota de Bones Pràctiques: `git add .` vs. Fitxers Concrets

L'ús de git add . és totalment acceptable i ràpid sempre que abans hagis configurat bé el teu fitxer .gitignore i hagis revisat amb git status què s'està incloent.

Si vols un control més granular (per exemple, per fer un commit només d'un script i no d'una escena a mig fer), pots afegir fitxers o carpetes de manera individual: 

git add Assets/Scripts/PlayerController.cs
7

Branques com a Entorn d'Experimentació

Les branques no només serveixen per a equips. Un desenvolupador individual pot utilitzar una branca com a "sorral" (*sandbox*) per provar una mecànica arriscada sense arruïnar la versió principal que funciona. 

# Crea i canvia a una branca d'experimentació
git switch -c experiment/ia-enemics

# Programa, prova i fes els teus commits...
git add .
git commit -m "feat: proves inicials de navegació amb NavMesh"

# Si l'experiment és un èxit, torna a main i fusiona
git switch main
git merge experiment/ia-enemics

# Si l'experiment ha fallat, simplement torna a main i esborra la branca
git switch main
git branch -D experiment/ia-enemics
8

Marcat de Versions Estables (Etiquetes / Tags)

Utilitza etiquetes per a fixar puntals o fites en el desenvolupament (p. ex., fites de lliurament de pràctiques o la versió final d'una Game Jam). 

# Crea una etiqueta anotada a la versió actual
git tag -a v0.1.0 -m "Primera versió jugable amb moviment i nivell 1"

# Llista les etiquetes creades
git tag

# Publica les etiquetes al repositori remot
git push origin --tags
9

Resolució d'Emergències i Guia de Supervivència

1. Desfer canvis locals no desitjats

Restaura un fitxer concrete a l'estat del darrer commit:

git restore Assets/Scripts/PlayerController.cs

2. Moure canvis a mitges fent servir el "Calaix" (Stash)

Si tens canvis pendents i necessites canviar de branca o netejar l'entorn ràpidament: 

# 1. Guarda els canvis modificats al calaix temporal global
git stash

# 2. Canvia de branca o crea una de nova
git switch -c feature/nova-branca

# 3. Recupera els canvis i aplica'ls a la nova ubicació
git stash pop

3. Desfer un commit ja publicat de forma segura (`git revert`)

git revert crea un nou commit que inverteix exactament els canvis d'un commit anterior sense alterar l'historial compartit: 

# Consulta l'historial abreujat per a trobar el codi (hash) del commit
git log --oneline

# Reverteix el commit conflictor
git revert 
git push origin main
10

Treball Simultani: Aula vs. Casa

Molt habitual entre l'alumnat. Aquest és el procediment per a continuar el teu projecte des d'un ordinador nou o diferent sense generar conflictes de fusió:

PAS 1 Primera vegada en un ordinador nou (Clonador)

Assegura't de tenir instal·lat Git LFS al sistema (git lfs install) i descarrega el projecte des del repositori remot: 

git clone https://github.com/usuari/nom-repositori.git
PAS 2 Obrir el projecte a Unity

Obre Unity Hub, fes clic a Add project from disk, selecciona la carpeta descarregada i obre-lo. Unity regenerarà automàticament la carpeta local Library/ sense necessitat que estigui al repositori.

PAS 3 Si ja tenies la carpeta clonada prèviament

Abans d'obrir l'editor de Unity, descarrega sempre les darreres novetats del codi i dels assets binaris de LFS des de la terminal: 

git pull origin main
git lfs pull
