1

Introducció a les Interfícies en Unity (uGUI Canvas)

El sistema de UI clàssic de Unity (uGUI) es basa en l'element arrel Canvas. Tot element d'interfície visual (botons, textos, imatges o panells) ha de ser un fill directe o indirecte d'un Canvas per a poder ser renderitzat a pantalla.

Screen Space - Overlay

La interfície es dibuixa directament per sobre de la pantalla. Manté la mida fixa independentment de la càmera de joc. Ideal per a HUDs i menús principals.

Screen Space - Camera

El Canvas es renderitza a una distància fixa d'una càmera específica. Permet efectes de perspectiva, postprocessat o partícules afectant la UI.

World Space

El Canvas es comporta com un objecte 3D dins de l'escena. Indispensable per a barres de vida sobre caps d'enemics, pantalles diègetiques o Realitat Virtual (VR).

Ancoratge (Anchors) i RectTransform

Tots els GameObjects de UI tenen un component RectTransform en comptes del Transform habitual. Els Anchors (àncores) defineixen com es posiciona i escala un element de UI respecte al seu pare quan canvia la resolució o relació d'aspecte de la pantalla.

2

Components de UI per a Menús, Formularis i Taules

Per dissenyar pantalles de login, inventaris o taules de classificació (Leaderboards), utilitzem el paquet modern TextMeshPro (TMP) i els components de disseny automàtic.

Elements d'Entrada i Control

  • TextMeshPro - Text (TMP): Etiquetes de text d'alta qualitat basades en Vector SDF (Signed Distance Field).
  • TMP_InputField: Camp de text editable per a credencials o formularis.
  • Button (TMP): Botó interactiu amb esdeveniments OnClick().
  • Image / RawImage: Renderitzat de sprites 2D o textures dinàmiques d'API.

Contenidors i Layouts Dinàmics

  • Vertical / Horizontal Layout Group: Organitza automàticament els fills en columnes o files.
  • Grid Layout Group: Organitza els fills en quadrícules (ideal per a inventaris).
  • Content Size Fitter: Reajusta la mida del contenidor segons el contingut fill.
  • Scroll Rect: Permet fer scroll vertical/horitzontal en llistes llargues de dades.

Exemple de Codi: Control de Formulari amb TextMeshPro

using UnityEngine;
using TMPro;
using UnityEngine.UI;

public class LoginPanelUI : MonoBehaviour
{
    [SerializeField] private TMP_InputField _usernameInput;
    [SerializeField] private TMP_InputField _passwordInput;
    [SerializeField] private Button _submitButton;
    [SerializeField] private TextMeshProUGUI _statusText;

    private void Awake()
    {
        // Vincular l'esdeveniment del botó per codi
        _submitButton.onClick.AddListener(OnSubmitClicked);
    }

    private void OnSubmitClicked()
    {
        string user = _usernameInput.text;
        string pass = _passwordInput.text;

        if (string.IsNullOrEmpty(user) || string.IsNullOrEmpty(pass))
        {
            _statusText.text = "Error: Omple tots els camps!";
            return;
        }

        _statusText.text = $"Enviant dades de {user}...";
    }
}

3

Arquitectura REST API i Verbs HTTP

Una API REST (Representational State Transfer) és un servei web que permet al nostre joc intercanviar dades amb un servidor mitjançant el protocol HTTP. Les operacions estàndard segueixen l'esquema CRUD (Create, Read, Update, Delete).

GET (Read) Obté dades del servidor sense modificar-les. Ex: Descarregar la taula de puntuacions.
POST (Create) Envia dades noves al servidor per crear un recurs. Ex: Registrar un usuari nou.
PUT (Update) Actualitza un recurs existent al servidor. Ex: Desar la nova posició de l'inventari.
DELETE (Delete) Elimina un recurs específic del servidor. Ex: Esborrar un personatge guardat.

Execució Asíncrona: Corutines, `async/await` i el Fil Principal (Main Thread)

Les peticions a un servidor web o les tasques d'espera triguen temps en completar-se (latència de xarxa, processament). Per evitar bloquejar l'aplicació, s'han d'executar de forma asíncrona i no bloquejant.

Com funciona el fil principal de Unity (Main Thread)?

Unity és un motor basat essencialment en una arquitectura monofil (Single-threaded). Tota la lògica de gameplay, les entrades de l'usuari (Input), la física, les crides de cicle de vida (Start, Update) i el renderitzat de la pantalla s'executen en un únic fil d'execució: el Main Thread.

CICLE DE VIDA PER FOTOGRAMA (FRAME CYCLE)
Frame Start Input Update() Corutines Renderitzat

Per què mai hem d'usar Thread.Sleep()?

Si executes Thread.Sleep(3000) dins d'un Update(), indiques al sistema operatiu que aturi per complet el fil principal durant 3 segons.

Resultat: El joc es congela a 0 FPS, la finestra deixa de respondre, la UI no es dibuixa i no es processa cap entrada de teclat o ratolí.

Com ho soluciona la Corutina (yield return)?

La paraula clau yield return no atura el fil. Simplement "pausa" l'execució d'aquell mètode concret i torna el control immediatament a Unity.

Resultat: Unity continua renderitzant els següents fotogrames a 60+ FPS i, quan es compleix la condició d'espera, repren la corutina des del mateix punt.

Exemple Pràctic: Pausa d'Execució Sense Bloquejar el Joc

using System.Collections;
using UnityEngine;

public class CooldownExample : MonoBehaviour
{
    private void Update()
    {
        if (Input.GetKeyDown(KeyCode.Space))
        {
            // ❌ INCORRECTE: Congela tot el joc durant 3 segons (0 FPS)
            // System.Threading.Thread.Sleep(3000);

            // ✔️ CORRECTE: Inicia una execució pausada no bloquejant
            StartCoroutine(SkillCooldownCoroutine());
        }
    }

    private IEnumerator SkillCooldownCoroutine()
    {
        Debug.Log("Habilitat utilitzada!");

        // Pausa NOMÉS aquesta corutina durant 3 segons.
        // El Main Thread continua processant la resta del joc a 60 FPS.
        yield return new WaitForSeconds(3.0f);

        Debug.Log("Habilitat recarregada i a punt!");
    }
}

Peticions HTTP amb `UnityWebRequest`

La classe UnityWebRequest és el mòdul oficial de Unity per a gestionar peticions HTTP/HTTPS. A continuació es mostren les eines principals per executar peticions GET i POST.

1. Execució d'una Petició GET (Dins d'una Corutina)

using System.Collections;
using UnityEngine;
using UnityEngine.Networking;

public class NetworkManager : MonoBehaviour
{
    private const string API_URL = "https://ce-videojocs.free.beeceptor.com/api/v1/store/items";

    public void FetchStoreItems()
    {
        StartCoroutine(GetRequestCoroutine(API_URL));
    }

    private IEnumerator GetRequestCoroutine(string url)
    {
        using (UnityWebRequest webRequest = UnityWebRequest.Get(url))
        {
            // Espera fins que la petició es completi
            yield return webRequest.SendWebRequest();

            if (webRequest.result == UnityWebRequest.Result.Success)
            {
                Debug.Log("Resposta rebuda: " + webRequest.downloadHandler.text);
            }
            else
            {
                Debug.LogError($"Error de xarxa [{webRequest.responseCode}]: {webRequest.error}");
            }
        }
    }
}

2. Execució d'una Petició POST amb dades JSON

private IEnumerator PostRequestCoroutine(string url, string jsonBody)
{
    using (UnityWebRequest webRequest = new UnityWebRequest(url, "POST"))
    {
        byte[] bodyRaw = System.Text.Encoding.UTF8.GetBytes(jsonBody);
        webRequest.uploadHandler = new UploadHandlerRaw(bodyRaw);
        webRequest.downloadHandler = new DownloadHandlerBuffer();
        webRequest.SetRequestHeader("Content-Type", "application/json");

        yield return webRequest.SendWebRequest();

        if (webRequest.result == UnityWebRequest.Result.Success)
        {
            Debug.Log("Dades enviades correctament!");
        }
        else
        {
            Debug.LogError("Error en enviar dades POST: " + webRequest.error);
        }
    }
}

Tractament de Dades JSON: Serialització, Deserialització i DTO

Les APIs REST intercanvien la informació en format JSON (JavaScript Object Notation). Per a treballar amb aquestes dades en C#, utilitzem el patró DTO (Data Transfer Object): classes senzilles marcades amb [System.Serializable] que fan de plantilla entre el text JSON i els objectes de C#.

Serialització (Objecte C# ➔ Text JSON)

Procés de convertir una instància de C# o DTO en memòria viva a una cadena de text formatada en JSON. Indispensable per a enviar dades al servidor mitjançant peticions POST o PUT.

Deserialització (Text JSON ➔ Objecte C#)

Procés invers: agafa la cadena de text JSON rebuda d'una petició GET i la reconverteix en instàncies d'objectes C# amb els seus camps i tipus de dades a punt per a utilitzar.

JsonUtility de Unity vs. Newtonsoft.Json (`JsonConvert`)

El mòdul natiu JsonUtility és extremadament ràpid, però té una gran limitació: no pot deserialitzar arrays o llistes arrel directament (com [{"id":1}, {"id":2}]) a menys que s'embolcallin dins d'un objecte Wrapper.

Per als projectes professionals s'utilitza el paquet Newtonsoft.Json (instal·lable des del Package Manager de Unity com com.unity.nuget.newtonsoft-json), el qual permet serialitzar i deserialitzar qualsevol llista o array arrel de manera directa amb JsonConvert.DeserializeObject<List<StoreItemDTO>>(jsonString).

Exemple Complet: Serialització i Deserialització Correcta

using System;
using System.Collections.Generic;
using UnityEngine;
using Newtonsoft.Json; // Requereix el paquet com.unity.nuget.newtonsoft-json

// 1. Definim el DTO (Plantilla de dades)
[Serializable]
public class StoreItemDTO
{
    public string itemID;
    public string itemName;
    public int cost;
    public bool isAvailable;
}

public class JsonSerializationExample : MonoBehaviour
{
    private void Start()
    {
        // ===================================================
        // A. SERIALITZACIÓ: De DTO (C#) a Cadena de text JSON
        // ===================================================
        StoreItemDTO itemToUpload = new StoreItemDTO
        {
            itemID = "wpn_99",
            itemName = "Rifle de Plasma",
            cost = 1200,
            isAvailable = true
        };

        // Opció 1: Serialització amb JsonUtility (Natiu de Unity)
        string jsonFromNative = JsonUtility.ToJson(itemToUpload, true);

        // Opció 2: Serialització amb Newtonsoft.Json
        string jsonFromNewtonsoft = JsonConvert.SerializeObject(itemToUpload, Formatting.Indented);

        Debug.Log("<color=cyan>[SERIALITZACIÓ POST] JSON Generat per enviar al servidor:</color>\n" + jsonFromNewtonsoft);


        // ===================================================
        // B. DESERIALITZACIÓ: De Cadena JSON a Objectes C#
        // ===================================================
        // Imaginem que el servidor ens respon amb aquest JSON (Array arrel):
        string jsonResponseFromGet = "[{\"itemID\":\"wpn_01\",\"itemName\":\"Espasa\",\"cost\":150,\"isAvailable\":true},{\"itemID\":\"arm_02\",\"itemName\":\"Escut\",\"cost\":300,\"isAvailable\":false}]";

        // Amb Newtonsoft.Json deserialitzem un ARRAY ARREL directament a una List<StoreItemDTO>:
        List<StoreItemDTO> downloadedItems = 
            JsonConvert.DeserializeObject<List<StoreItemDTO>>(jsonResponseFromGet);

        Debug.Log("<color=green>[DESERIALITZACIÓ GET] Llista d'objectes processada:</color>");
        foreach (StoreItemDTO item in downloadedItems)
        {
            Debug.Log($"- Item: {item.itemName} | Preu: {item.cost} | Disponible: {item.isAvailable}");
        }
    }
}
